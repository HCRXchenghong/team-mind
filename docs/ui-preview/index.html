01 · Requirement profile

这个产品到底需要什么

不是“哪个库好看”，而是哪套组件能覆盖 TeamMind 最重的六类界面，并且让 20–50 人团队的日常操作不别扭。

01

高密度数据表格

任务、项目、成员、组织审核、审计日志：多条件筛选、排序、分页、行内操作、固定列、空状态。

TablePaginationFixed columns
02

表单与审批流

新建/编辑弹窗、抽屉详情、提案变更、审批决策：校验、只读态、危险操作二次确认。

FormModalDrawer
03

AI 对话界面

流式 Markdown、代码块、会话列表、工具调用结果、逐次授权开关；观感要像 AI 产品，而不是后台。

StreamingMarkdownToken
04

时间轴与甘特

按天渲染、里程碑、依赖、今日线、120 天上限；没有库会内置，需要好的基础控件 + 自研 SVG/Canvas。

05 · Recommendation

结论：最终采用 Ant Design Vue

如果目标是“重做一版有自己气质的 AI 协作工作台”，Naive UI 的主题系统与观感最合适；如果目标是“三个月内把 14 个页面全部补齐”，Ant Design Vue 最省事。

当时评分第一

Naive UI

v2.45 · MIT · TypeScript 优先

主题覆盖能力是六个里最强的：一套 themeOverrides 就能长出 TeamMind 自己的设计语言，暗色是原生一等公民，体积也最友好。

  • 表格、表单、树、穿梭框、日期、上传都齐全
  • AI 对话界面干净，不像“管理后台”
  • 需要自建 Pro 壳（导航/标签页/面包屑）
  • 中文文档偏少，团队需接受英文文档
最终采用 · 交付最快

Ant Design Vue

v4.2 · MIT · 企业级事实标准

组件最全、表格/表单/审批的模式最成熟，社区模板和中文资料最多；代价是视觉同质化、包体偏大。

  • 14 个页面可以最快复刻，风险最低
  • ConfigProvider + darkAlgorithm 主题够用
  • Pro 壳需要照搬 Arco Pro 的结构重写
  • 容易看起来“和别的后台一样”
品牌向 · 高投入

shadcn-vue

复制式组件 · Tailwind CSS

最像现代 AI 产品，设计完全归你；但数据表格、筛选、甘特、表单校验都要自己组装，工期显著更长。

  • 对话、落地页、设置页会非常出彩
  • TanStack Table 可做出更强的任务表
  • 需要稳定设计系统与前端人力
  • 中文/复杂表单生态最弱
◎
其余三个怎么放： Element Plus 只在“团队已经熟、招聘优先”时选；TDesign 适合未来要做 IM/审批中台的路线；Arco 是刚删掉的那一版，除非想沿用现有组件习惯，否则不建议原地打转。
甘特图单独立项：无论选谁，时间轴都要自研或引第三方，建议先做只读渲染 + CSV 导出，再接依赖连线与 AI 体检。
06 · Rebuild plan

定库之后的四步

前端代码已清空，仓库只剩后端、脚本与文档。建议按下面顺序起新工程，避免又长成第二个“能跑但难维护”的版本。

定库 + 设计 token

拍板 Naive UI 或 Ant Design Vue；先定色板、圆角、字号、间距、暗色映射，写进 tokens.css，再写第一个页面。

搭壳与请求层

顶栏/侧栏/标签页/面包屑、组织切换、SSE 未读、401 拦截、分页与错误归一化。壳不稳，页面越多越乱。

按依赖顺序迁页

登录 → 总览 → 任务 → 项目 → 甘特 → 审批 → 成员/部门 → 通知 → 设置 → AI → 平台。每页对着清单验收接口。

AI 与甘特单独攻坚

流式 SSE、Markdown 消毒、逐次授权、工作区文件；甘特时间轴 SVG + 依赖 + 分享 token。这两块不要塞进通用组件里。
